# Smart Listing Classifier

> **NLP-проект для автоматической классификации текстовых объявлений по категориям**

Smart Listing Classifier исследует различные подходы к классификации объявлений на основе их заголовка и описания.

Проект создан как учебный NLP-кейс, близкий по постановке задачи к классификации объявлений на маркетплейсах и классифайдах.

---

## 📌 О проекте

Модель получает текст объявления и определяет, к какой категории оно относится.

В проекте используются **6 категорий**:

* 💻 Электроника
* 🛋️ Мебель
* 🚗 Автомобили
* 👕 Одежда
* 🏠 Недвижимость
* 🛠️ Услуги

> **Важно:** проект использует синтетический учебный датасет, созданный специально для экспериментов. Он не содержит реальных данных Avito и не отражает production-систему Avito.

---

## 🎯 Цель проекта

Исследовать, как различные способы представления текста влияют на качество классификации объявлений.

В проекте последовательно сравниваются:

1. **TF-IDF**
2. **TF-IDF + биграммы**
3. **Character-level TF-IDF**
4. **RuBERT embeddings**

---

## 📊 Датасет

Каждая запись содержит:

| Поле          | Описание                                |

| `title`       | Заголовок объявления                    |
| `description` | Описание объявления                     |

| `text`        | Объединённый текст заголовка и описания |

### Распределение категорий

Датасет сбалансирован:

| Категория    | Количество |
| ------------ | ---------: |
| Электроника  |         70 |
| Мебель       |         70 |
| Автомобили   |         70 |
| Одежда       |         70 |
| Недвижимость |         70 |
| Услуги       |         70 |
| **Всего**    |    **420** |

### Разделение данных

* **80%** — обучающая выборка

Разделение выполняется **стратифицированно**, чтобы сохранить одинаковое распределение категорий в обучающей и тестовой выборках.

# 🧪 Эксперименты

## 1. TF-IDF + Logistic Regression

Первый эксперимент использует классическое представление текста **TF-IDF** совместно с Logistic Regression.

Результат на Dataset v1:

### Accuracy: `1.000`

Однако дальнейшее ручное тестирование выявило проблемы с некоторыми формулировками, которые отличались от примеров обучающей выборки.

---

## 2. TF-IDF + биграммы

В следующем эксперименте к униграммам были добавлены биграммы:

```python
ngram_range=(1, 2)
```

Это позволило учитывать не только отдельные слова, но и короткие словосочетания.

**Результат:**

### Accuracy: `1.000`

---

## 3. Расширение датасета

После анализа ошибок Dataset v1 был расширен.

Количество объектов увеличилось:

**360 → 420**

В Dataset v2 появились дополнительные варианты формулировок внутри каждой категории.

На новом датасете TF-IDF + Logistic Regression показал:

### Accuracy: `0.988`

При этом снижение Accuracy сопровождалось улучшением поведения модели на некоторых новых примерах.

### Пример

**Объявление:**

> Кожаный диван в хорошем состоянии, возможен торг

На первоначальном варианте модели объявление ошибочно классифицировалось как:

`Автомобили`

После расширения датасета модель определила его как:

`Мебель`

Этот пример показал, что увеличение разнообразия обучающих данных помогает модели лучше обрабатывать ранее не встречавшиеся формулировки.

---

## 4. Error Analysis

Отдельно анализировались ошибки модели.

### Пример ошибки

> Пуховик. Зимний пуховик, почти не носили

TF-IDF-модель определила объявление как:

`Недвижимость`

Анализ словаря показал, что следующие слова отсутствовали в словаре модели:

* `пуховик`
* `зимний`
* `носили`

При этом значимым активным признаком оказалось слово:

`не`

Этот пример продемонстрировал ограничение **word-level TF-IDF** при работе с небольшим датасетом и ранее не встречавшимися словами.

---

## 5. Character TF-IDF

Для проверки альтернативного подхода был использован **character-level TF-IDF**:

```python
analyzer="char"
ngram_range=(3, 5)
```

Количество признаков:

**9 873**

Результат:

### Accuracy: `0.976`

Таким образом, увеличение количества признаков само по себе не привело к улучшению качества классификации.

---

## 6. RuBERT Embeddings

Финальный эксперимент использует модель:

```text
cointegrated/rubert-tiny2
```

RuBERT используется для получения **контекстных представлений текста**.

Полученные embeddings передаются в Logistic Regression.

**Размер embedding:**

`312 признаков`

**Результат:**

### Accuracy: `1.000`

# 🧩 Robustness Test

Помимо стандартного `train/test split`, модель была проверена на вручную составленных объявлениях с менее очевидными ключевыми словами.

### Пример 1

**Текст:**

> Продам удобный предмет для дома, мягкий и большой

**Предсказание:**

`Мебель`

**Уверенность:**

`0.775`

### Пример 2

**Текст:**

> Устройство для работы и учёбы, хорошее состояние

**Предсказание:**

`Электроника`

**Уверенность:**

`0.759`

Модель правильно определяла категории, однако на менее информативных текстах её уверенность снижалась.

Это показывает, что **правильное предсказание не всегда означает высокую уверенность модели**.

# 🔮 Inference

В проекте реализована функция `predict_listing()`, которая принимает текст нового объявления и возвращает:

* предсказанную категорию;
* вероятность каждой категории.

### Пример

```python
text = """
Продаю ноутбук Lenovo IdeaPad.

16 ГБ оперативной памяти, SSD 512 ГБ.

Подходит для работы и учёбы.
"""

prediction, probabilities = predict_listing(text)

print(prediction)
print(probabilities)
```

**Результат:**

```text
Электроника
```

# ⚠️ Ограничения

Результаты проекта нельзя напрямую переносить на реальные объявления.

Основные ограничения:

* небольшой размер датасета;
* синтетические данные;
* регулярность некоторых формулировок;
* отсутствие реальных пользовательских объявлений;
* отсутствие production-like validation set;
* высокая вероятность того, что тестовая выборка проще реальных данных.

Поэтому **Accuracy = 1.000** следует рассматривать как результат эксперимента на данном учебном датасете, а не как оценку качества production-модели.
